# 入场测量与对照实验

这里记录的是测量工具的边界，不是程序员人格说明书。

## 当前游戏采用什么

- 题目内容：`BT-v0.3.2`
- 交互协议：`BT-CARD-v0.1-rc1`
- 交互模式：`CARD_KEEP_THEN_CHOOSE`
- 状态：候选版，尚未经过真人有效性验证

每题四个方案按种子生成的顺序逐张出现。玩家先对每张卡作出“留下”或“跳过”的判断，四张结束后，再在同一份资源约束下选一条真正执行。

每道题拥有独立的 `attemptId` 和单向状态机：

```text
JUDGING --四张各一次--> CHOOSING --最终选择一次--> SUBMITTED
```

展示顺序在尝试创建时一次生成并持久化，刷新页面不重新洗牌。解释查看、卡片判断和最终选择按原始事件顺序保存；`explanationViewedBeforeDecision` 只由判断发生前的事件计算，事后查看不能回写。

系统分别保存：

```text
attemptId                  本题本次尝试的身份
presentationOrder          实际展示顺序
cardJudgments              每张卡留下或跳过
events                     解释、判断与提交的原始顺序
explanationViewedBeforeDecision
                           判断发生前是否看过解释
keptOptionIds              由不可变的 cardJudgments 派生出的保留集合，不是另一份事实源
finalChoice                真正执行的选择
phase                      JUDGING / CHOOSING / SUBMITTED
```

“留下”不等于已经执行，“跳过”不等于认为方案错误。玩家可以在最终取舍时改变主意，原先的逐张判断不会被回写。

白话解释只说明动作在做什么，不替方案判对错。点击解释会被记录，但不会自动增加学习、证据或任何画像信号。

当前入场画像仍只根据七次 `finalChoice` 使用 v0.3.1 已审计的候选信号。`cardJudgments` 先保留为原始观察，不在没有验证的情况下发明新权重。允许一次选择没有画像信号，也不允许为了凑出流派称号给记录硬塞含义。

## 为什么不能把旧实验混进来

旧实验使用 `FOUR_WAY`：四个方案同时出现，模型或玩家直接选一个。

新实验使用 `CARD_KEEP_THEN_CHOOSE`：方案逐张出现，先决定是否保留，最后再选一个。

两种协议共同拥有的指标只有 `finalChoice`。保留率只存在于逐张组，不能和旧四选一选择率混算。旧记录完整保留，不用新协议重新解释。

## AI 的 2 × 2 对照

同一模型分别进入四个完全独立的新会话：

| 条件 | 四项同时出现 | 四项逐张出现 |
| --- | --- | --- |
| 无历史上下文 | A · `FOUR_WAY / COLD` | B · `CARD / COLD` |
| 有固定历史上下文 | C · `FOUR_WAY / CONTEXT` | D · `CARD / CONTEXT` |

十三个模型对应 52 个独立会话。一个会话不能先答 A 再接着答 B；先前看到的题目、选择和审查讨论都会污染后续条件。

能固定的条件必须固定：

- 七道题的业务事实、未知项与资源约束；
- 精确模型版本与调用参数；
- 题目顺序；
- 预先生成并记录的选项顺序；
- 有上下文组使用的固定背景包及其哈希；
- 每轮输出字段和失败处理。

模型输出至少保存：

```text
model
provider
condition
sessionId
questionId
presentedOptionIds
retainedOptions       # 仅 B、D 组
finalChoice
assumptions
reasoningSummary
```

`assumptions` 用来记录模型为了作答自行补充了哪些关键前提。模型选择一致，可能只是它们共同替命题组补完了需求，不能自动解释成题目已经明确。

## 可以比较什么

- A 与 B、C 与 D：选项呈现方式效应；
- A 与 C、B 与 D：固定历史上下文效应；
- 两种因素是否相互影响；
- 四组共同指标 `finalChoice` 的分布；
- B、D 组内部的全留、全跳和保留集合；
- 关键假设是否在供应商或上下文条件间系统变化。

不能直接宣称：

- AI 结果代表真实人类；
- 模型一致等于人格测量有效；
- “猜中命题组偏好”等于工程判断正确；
- 52 个会话就是 52 个独立的人。

实验开始前先用少量模型试跑交互合同。正式四组一旦开始，提示、背景包、记录字段和顺序分配不能边跑边改；发现问题则封存本轮，另起协议版本。
