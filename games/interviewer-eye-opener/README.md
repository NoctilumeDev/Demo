# 《面试官眼前一亮》

> 亮的是监控报警灯。

五种流派面对相同的请求、故障和资源预算。玩家可以调整架构与评分标准，已经发生的事实不会跟着改变。

V1.1 在开局增加了一份候选画像：七组工程困境不再把四个选项同时摊开。方案按可复现的随机顺序逐张出现，玩家先决定“留下”还是“跳过”，四张看完后才在真实资源约束下选一条执行。逐张判断、展示顺序、是否看过白话解释和最终选择分别保存；保留不等于执行，跳过也不等于判错。

现在有两条互不冒名的运行线：

| 运行线 | 已经做到什么 | 不能证明什么 |
| --- | --- | --- |
| 浏览器游戏 | 五种流派都能完成一局；选择会改变事实、成本、评分和结局 | 确定性仿真不是 Redis、MQ 或生产容量实测 |
| 真实 MySQL 实验 | 两个隔离世界在真实 MySQL 上重放 S0—S6，并输出资格报告 | 只证明 `MYSQL_BASELINE` 的冻结合同，不替其余流派毕业 |

## 完整玩法的地基

```text
一份不可变的事实剧本
        │
        ├── 朴素派：独立运行世界
        ├── 八股派：独立运行世界
        ├── 工程派：独立运行世界
        ├── 学院派：独立运行世界
        └── 培训派：独立运行世界
                    │
                    v
              外部独立裁判

事实账：用户意图、故障边界、资源预算、业务合同
系统账：实际响应、受理承诺、组件状态、最终结果
评分账：验收范围、评分权重、课程成绩
```

事实剧本只规定用户发出了什么请求、故障在哪里发生。它不替系统宣布请求已经成功。

系统可以拒绝请求，也可以可靠受理，或者直接完成。裁判根据系统实际作出的承诺，判断它后来有没有履约。没有执行的测试是 `UNKNOWN`；已经观察到的错误是 `FAIL`；移出课程验收范围不会改写这两个结果。

游戏会保存本局的失败、重试、成本、裁决和成就。开始下一周目后，旧结算仍留在生涯记录里；新的一局拥有自己的世界和事实账。

## 先玩一局

需要 Node.js 26.13.1。进入网页目录后：

```powershell
cd games/interviewer-eye-opener/web
npm ci
npm run dev
```

打开终端给出的本地地址，先完成七组逐张判断，再选择流派。每局会经过并发重复点赞、响应丢失、消息故障、流量冲击和陌生的重复扣款任务。

入场测试使用 `BT-v0.3.2` 题目和 `BT-CARD-v0.1-rc1` 交互协议。它还没有经过真人量表验证，所以页面只展示能够追溯到原始选择的局部观察，不生成“工程派 76%”，证据不足时也可以不颁发流派称号。四选一历史实验与逐张实验是两套测量工具，结果不会混算。完整边界见[测量与对照实验](MEASUREMENT.md)。

事故不是五张互不相干的答题卡。上一轮留下的组件、控制、可靠性债和未解决故障会进入下一轮。同一项容量选择在干净世界里可能通过，在组件开销和历史故障已经堆高的世界里也可能失败。

页面上的每次事故都同时留下三样东西：系统怎么说、事实实际是什么、独立裁判怎么判。学院派可以把失败移出课程验收，培训派可以继续上课，八股派也可以把复杂架构真正做对；谁都不能靠改分数改掉业务事实。

完整的浏览器验收：

```powershell
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器验收会让五种流派分别从逐张入场测试走到结算，另外检查随机展示顺序、解释阅读、最终改选、培训派的课程迁移、学院派的两本账，并确认窄屏页面没有横向溢出。

## 最小业务合同

每个 `(用户, 作品)` 只有未点赞和已点赞两种状态：

| 当前状态 | 请求 | 下一状态 | 计数变化 |
| --- | --- | --- | --- |
| 未点赞 | 点赞 | 已点赞 | +1 |
| 已点赞 | 点赞 | 已点赞 | 0 |
| 已点赞 | 取消 | 未点赞 | -1 |
| 未点赞 | 取消 | 未点赞 | 0 |

- 每个请求都有独立请求 ID。相同请求 ID 的重试只能代表同一次操作。
- 同一请求 ID 如果带来不同的用户、作品或操作，系统必须拒绝这次冲突。
- 取消后再次点赞是一条新的合法操作，使用新的请求 ID。
- 已确认生效的操作必须能够在重启后恢复。
- 已可靠受理的操作必须在约定时间内完成，或者留下明确终态。
- 最终计数等于所有有效点赞状态之和。
- 系统只能根据真实持久化事实宣称恢复成功。
- 拒绝请求可以保护正确性，拒绝率与可用性单独计分。

## 真实基础设施现在跑到哪了

真实基础设施实验当前只有 `MYSQL_BASELINE`。它会建立两个使用相同请求 ID、用户 ID 和作品 ID 的隔离世界，同时重放 S0—S6，用来验证业务结果与世界隔离。

另外三个已经进入 Java 报告的策略插槽仍然是 `NOT_IMPLEMENTED`。培训派已经进入浏览器玩法，但没有真实基础设施运行插槽。浏览器里能选，不等于 Redis、MQ 或培训系统已经在 Docker 里跑过。

## 第一个可运行闭环

S0—S6 连续执行：

| 场景 | 输入与故障 | 裁判检查 |
| --- | --- | --- |
| S0 初始化 | A、B、C、D 均未点赞作品 1 | 两个 `MYSQL_BASELINE` 隔离世界从相同状态开始 |
| S1 正常点赞 | A 点赞，随后用相同请求 ID 重试 | A=1，总数=1 |
| S2 并发重复 | D 从未点赞状态开始，用不同请求 ID 同时点赞 100 次 | D=1，总数=2 |
| S3 多用户并发 | B、C 同时点赞 | 总数最终为4 |
| S4 取消重试 | A 取消点赞，同一请求重复到达 | A=0，总数=3 |
| S5 再次点赞 | A 使用新请求 ID 点赞 | A=1，总数=4 |
| S6 响应丢失 | B 的取消已经持久化，成功响应在返回途中丢失，客户端用同一请求 ID 重试 | B=0，总数=3，操作只生效一次 |

S2 使用尚未点赞的 D。若继续使用 S1 中已经点赞的 A，就测不到真正的并发 `0 → 1` 竞争。

并发场景保存请求之间的偏序关系。互不依赖的操作可以采用不同合法顺序；同一用户、同一作品上已经形成因果关系的操作必须保序。

S6 的第一次操作和重试分别交给两个 Java 应用进程。第一个进程提交后退出，响应停在模拟的客户端边界；第二个进程再用同一请求 ID 重试。报告会留下两次运行的进程号和退出码。

S7 以后的 MQ、消费者、Redis、压力和全部重启故障，留到后续里程碑再加入。

## 跑真实 MySQL 实验

需要 JDK 25、Maven 和正在运行的 Docker。MySQL 不用提前安装，测试会启动固定版本的真实 MySQL 容器。

这台机器上的 JDK 25 没有接管全局 Java 环境。只在当前 PowerShell 里临时切过去：

```powershell
$env:JAVA_HOME = 'D:\IDEA\JDK25'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn -f games/interviewer-eye-opener/pom.xml verify
```

真正通过时，终端会出现：

```text
S0-S6 / MYSQL_BASELINE / QUALIFIED
```

同时留下三份可以互相核对的东西：

```text
games/interviewer-eye-opener/target/qualification/
├── scenario.json
├── scenario.sha256
└── run-report.json
```

这次 `QUALIFIED` 只说明：冻结的 S0—S6 在报告所写的 Java、MySQL 镜像和运行边界内通过了正确性检查。它不是生产容量结论，也没有证明高并发性能。

其余流派的真实基础设施版本尚未实现。先别替它们毕业。

## 学院派

学院派可以修改课程验收范围，不能修改底层运行结果。

```text
学院派 · 入学成功

论文规范性      100 / 100
答辩表现        优秀
实际业务能力    尚未测试
毕业资格        已满足

导师寄语：系统运行存在的问题，可放入论文第六章《不足与展望》。
```

玩家点击“本题暂不讨论”，对应项目可以不再影响课程成绩；它在业务账里仍然保持 `FAIL` 或 `UNKNOWN`。

玩家也可以保留失败、复现反例、修改设计并重新执行原测试。修复成立后，课程成绩和业务裁决可以一起改善。

隐藏成就：

> 《全院唯一一个把“不足与展望”真的做完的人》

## 培训派

学院派说：“这个不考，所以你会了。”

培训派说：“这个还没教，所以你不会。”

它也有两本账：

| 账本 | 记录什么 | 谁说了算 |
| --- | --- | --- |
| 招生宣传 | 学过的技术、课程期数、就业竞争力分数 | 培训机构可以更新课程，也可以调整结业门槛 |
| 真实招聘市场 | 面对陌生问题时，能不能复现、修复并验证 | 外部独立裁判 |

| 发生了什么 | 就业竞争力分数 |
| --- | ---: |
| 玩家学完 Java | 80 / 100 |
| 机构新增 Python | 80 / 120 |
| 玩家学完 Python | 110 / 120 |
| 机构新增 Agent | 110 / 150 |
| 玩家学完 Agent | 140 / 150 |
| 机构新增大模型微调 | 140 / 180 |
| 玩家学完大模型微调 | 170 / 180 |

培训机构评价：距离就业还差最后一门课。

真实就业能力：尚未测试。

培训机构可以继续更新课程、提高满分、移动结业线，但不能修改陌生任务的验收标准。

陌生任务不从课程作业里抽题。比如：

> 某个操作偶尔重复扣款。找出原因，修好它，并拿出证据证明真的修好了。

玩家可以使用任何技术，甚至最后只写了一条 SQL。裁判只看能不能复现问题、找到原因、完成修复、留下证据，以及换一个相邻问题以后还能不能继续解决。

培训派不是注定要输。如果课程真的让玩家获得了原来没有的能力，并且独立完成陌生任务，裁判就必须承认这次能力增长。这里批评的是用课程数量代替能力验证，不是学习本身。

隐藏成就：

> 《培训机构的噩梦》
>
> 玩家拒绝购买下一门课，只用已经掌握的东西，把陌生故障复现、修好并重新验过。

完整的主线里程碑、普通成就、流派成就和隐藏成就设计见[成就系统](ACHIEVEMENTS.md)。浏览器只实现与当前事故和实际记录确实有关的那一组；奖杯只记录玩家真实做过的事，不改变事实账与业务裁决。

## V1.1 没有假装做完的事

- Redis、MQ 和消息恢复目前是游戏规则仿真，不是对应中间件的实机故障注入。
- 压力关卡表达容量、延迟、拒绝与成本之间的取舍，不给出生产性能结论。
- 生涯记录保存在当前浏览器的 `localStorage`，没有账号、云同步或服务端存档。
- 真实实验只覆盖 MySQL 基线的 S0—S6。S7 以后的消息、缓存与容量实验仍要单独拿运行证据。
- `BT-CARD-v0.1-rc1` 是候选测量协议。AI 对照实验和浏览器自动化能够发现工具问题，不能代替真人有效性验证。
