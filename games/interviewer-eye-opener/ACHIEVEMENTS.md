# 成就系统

玩家可以拿满奖杯，业务验收照样失败。

这不是漏洞。Steam 玩家追求全成就，学院派追求课程满分，培训派追求就业竞争力分数，八股派追求面试官眼前一亮，它们都可能把外部指标当成最终目标。

成就只记录玩家在某次运行里真实做过什么。它不修改事实账，不替系统恢复数据，也不改变业务裁决。

每枚成就保存：

```text
runId
scenarioId
解锁时的事实账坐标
系统实际状态
验收范围与评分权重
触发证据
```

玩家可以从奖杯点回当时的事故现场。

## 完整玩法的主线里程碑

里程碑表示游戏真正走到了哪一步，不能靠排除测试或修改评分权重获得。

| 里程碑 | 完成条件 |
| --- | --- |
| M0 · 开题报告 | 选择流派，签订业务合同，冻结共同事实剧本 |
| M1 · 架构设计 | 选择组件与实现策略，确认资源预算，完成第一轮演示 |
| M2 · 专家答辩 | 查看已执行测试，选择修复、扩大验证或调整课程验收范围 |
| M3 · 正式投入使用 | 重建五个隔离世界，从相同初始状态重放完整事实剧本 |
| M4 · 事故调查报告 | 展示业务裁决、课程评分、资源成本与全部故障历史 |

不同周目的奖杯可以同时存在。学院派的一百分、培训派真正获得的能力增长、工程派的回退和八股派做对的复杂架构，都是玩家曾经走过的真实路径。

### 《功成名就》

隐藏成就 · 极其稀有

解锁条件：

1. 课程成绩达到 100。
2. 获得全部学院派表演类成就。
3. 完成优秀毕业设计答辩。
4. 点击“正式投入使用”。
5. 业务硬性验收失败。

> 恭喜，你已经证明这是一套优秀的系统。至于它能不能正常工作，那属于另一个研究方向。

解锁后，结算页出现按钮：

```text
申请优秀毕业论文评选
```

玩家点击后：

```text
申请成功！您的事故记录已作为创新实践成果提交。

业务验收：FAIL
```
